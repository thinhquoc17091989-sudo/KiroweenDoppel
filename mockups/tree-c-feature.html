What this one optimises for

  • People ask "how does irrigation work?", not "where are the sequence diagrams". This groups a feature's static design with the views generated from its code, side by side.
  • A generated view sits next to the element it describes, so the link between the design and what the code actually does is visible without opening anything.
  • Staleness rolls up to the feature header, so one glance tells you which feature has drifted.
  • A Feature / Folder toggle switches to the literal path view for anyone who prefers it. Same files, two readings.
  • Approve writes into the feature folder shown in the breadcrumb, so a new proposal lands beside the diagrams it belongs with.

Where the layout is stored

  • .doppel/layout/<diagram>.json, committed, so a teammate opening the repo sees the diagram arranged the way you left it.
  • Outside architecture/, because steering feeds that folder to Kiro wholesale and coordinates are not design.
  • Keyed by element id and written sorted, so concurrent edits merge instead of conflicting.
