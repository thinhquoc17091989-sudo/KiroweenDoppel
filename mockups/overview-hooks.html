Hooks

What a hook is
A rule that makes Kiro act on an event instead of waiting to be asked. Doppel's whole "keeps it honest" promise rests on one: change the architecture, and the code follows without anyone remembering to ask.

What happens when you press Write & trigger

1
Doppel writes the file
Approved elements become architecture/*.puml, positions go to layout.json. Plain text, straight into your repo.
2
The hook fires
PostFileSave, matching architecture/.*\.puml$ — Kiro notices the save itself.
3
Kiro generates per element
src/<id>.ts and test/<id>.test.ts for anything new or changed. Untouched elements are left alone.
4
Low-level design too
The sequence, state and activity diagrams for that feature are written beside the code, so the design you review is the design that shipped.
5
Trace is recorded
update-trace.mjs stores each element's hash. Never hand-written — a guessed hash would make drift lie forever.
6
Drift is checked
Straight into the MCP tool on the next tab.

The hook itself

{
  "version": "v1",
  "hooks": [{
    "name": "On architecture change",
    "trigger": "PostFileSave",
    "matcher": "architecture/.*\\.puml$",
    "action": {
      "type": "agent",
      "prompt": "…generate code and
        low-level design for each
        changed element, then run
        update-trace.mjs"
    }
  }]
}

The catch, stated plainly

File hooks fire on changes the agent makes, not on a file a tool wrote from outside. That is why Doppel needs its own trigger (the button above) rather than relying on the save alone — and why a second hook runs the drift check on every prompt as a safety net.
