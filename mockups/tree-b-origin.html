What this one optimises for

  • The split that actually matters is authored versus generated. Editing a generated file by hand is always a mistake, so those carry a lock and sit in their own section.
  • Generated views are grouped by dialect, which is how you look for them: "show me the sequence diagrams".
  • Staleness is surfaced, not buried: a banner counts the generated files that no longer match the code, with one button to regenerate them.
  • The write destination is a control at the top, not a label. Pick the target file, then approve.
  • Best when dynamic diagrams outnumber static ones, which is what happens once code lands.

Where the layout is stored

  • .doppel/layout/<diagram>.json, committed, so the arrangement travels with the repo rather than living in one person's browser.
  • Never inside architecture/: steering hands that whole folder to Kiro as approved design.
  • Keys are element ids and sorted on write, so two people dragging different boxes produce a small, mergeable diff instead of a whole-file conflict.
