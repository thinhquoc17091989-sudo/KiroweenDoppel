Steering

What steering is
Files Kiro loads into context automatically, on every single request, without anyone pasting or re-explaining them. It is how Kiro knows your project's rules before it writes a line.

Doppel's steering files

architecture.md always
References every approved architecture/*.puml. This is the one that matters: it is why Kiro proposes a change to what exists rather than redrawing from scratch.
product.md always
Vocabulary (element, proposal, approved, stale, drift) and the hard rules: invented sample data only, never claim real SysML, no copied code.
tech.md always
Stack and conventions, so generated code matches the project instead of the model's defaults.

# Approved architecture

#[[file:architecture/*.puml]]

- Element ids are the stable identity.
- Code for an element goes in
  src/<element-id>.ts
- Record it with
  node mcp/update-trace.mjs <id>

Format decision

PlantUML stays the source of truth — not JSON, not Markdown. It is readable, it diffs cleanly in a pull request, and a person can hand-edit it. JSON is used only for index.json (what files exist, for this tree) and trace.json (element → code → test), never for the architecture itself.
